# Data, fixtures and provenance

| Resource | Included / availability | Scope and rights |
|---|---|---|
| `agrosim/crop_catalog/data/*.json` | Packaged small catalog/taxonomy/environment metadata | Existing GBIF/EcoCrop provenance retained; owner must review linked terms/attribution before public redistribution |
| `agrosim/api/data/living_fixture.json` | Packaged, repository-authored | Explicit hypothetical functional stocks/rates; no measured organism abundance |
| Controlled crop/rotation fixtures | Generated by existing repository fixture functions | Hypothetical soil/weather/management; offline, deterministic, no live source claim |
| `examples/api/*.json` | Packaged, generated requests/results | Declared demonstration inputs and actual computed outputs, not field observations |
| NASA POWER `power.json` | Optional operator resource; excluded | Existing `agrosim.data.power` parser validates variables/units/point/time; coarse-grid daily historical replay, no field-scale or future-weather claim |
| NASS/ERS/farmdoc | Research archive and source adapters preserved locally | API requires explicit supplied finance; automatic adoption remains unavailable in V1.0. Publication requires source attribution/terms review |
| SMAP/GPM/SRTM/Landsat/SoilGrids | Not integrated into release service | Never marked available solely because earlier research adapters exist |
| Research observations and reports | Preserved locally; excluded from handoff | Needed for full historical scientific regression, not offline API startup; some rights/access require independent review |
| User farm/run data | Generated private `AGROSIM_DATA_DIR` | Not public fixtures; includes user inputs, results, logs and UUID snapshots |
| Credentials/cache/virtualenv | Excluded | Never distributed |

A fresh installation can run `controlled_corn_v1` without NASA credentials,
local private paths, hidden observation files or network access after installing
dependencies. The included request explicitly adopts hypotheses; it does not
fabricate a field-specific initialization.

To use existing NASA data, the operator places a documented POWER JSON wrapper
at `<AGROSIM_RESOURCES_DIR>/power.json`. Keep the original returned header,
geometry, units, parameter dates and retrieval metadata. Request the same point
and source year. Missing/gapped/incompatible resources are unavailable; the API
does not fetch new datasets or silently create replacement observations.

Full archived scientific verification remains available in the original working
repository through `verify-platform` and `verify-crop-physiology`. Keep their
recorded configurations, raw observations and source manifests for reproduction.
The release handoff includes only runtime source, small fixtures, documentation
and HTTP tests; it does not pretend to contain all research datasets.
